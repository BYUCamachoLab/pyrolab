## 0.5.0 - 2026-10-05

A reliability release. The background daemon now starts, stops, and recovers
predictably; configuration is validated before it can cause trouble; all
logging goes to one file you can read with `pyrolab status` and
`pyrolab logs show`; and PyroLab's files have moved out of the installed
package. PyroLab now requires Python 3.11+ and pydantic 2.

### Upgrading from 0.4

- **Python 3.11 or newer is required.** On Python 3.9 or 3.10, pip keeps
  installing 0.4.0.
- **pydantic 2 is required** (#40). Existing configuration files load unchanged. Code
  that uses PyroLab's configuration models directly needs pydantic 2's API
  (`model_dump()` instead of `.dict()`, `model_validate()` instead of
  `parse_obj()`, and so on).
- **Your files have moved** from inside the installed package to your user
  folders: on Windows, `%LOCALAPPDATA%\pyrolab`; on Linux,
  `~/.config/pyrolab` and `~/.local/state/pyrolab`. The first `pyrolab`
  command after upgrading copies your configuration and nameserver databases
  there, once, without overwriting anything and leaving the originals in
  place. `pyrolab --data` shows every location, and `PYROLAB_DATA_DIR` keeps
  everything in one folder instead. Upgrading PyroLab no longer erases your
  configuration.
- **One log file.** The daemon writes a single `pyrolab.log` (one JSON record
  per line, rotated at 5 MB) for itself and every nameserver and daemon it
  runs, replacing the per-process `pyrolab_<pid>.log` files. Read it with
  `pyrolab status`, `pyrolab logs show`, or `pyrolab logs export`.
- **Importing `pyrolab` no longer changes your program's logging**, exception
  hook, or warning filters, and never contacts PyPI. Client scripts that want
  Pyro's remote tracebacks set `sys.excepthook = Pyro5.errors.excepthook`
  themselves.
- **Configuration comes only from the configuration file.** Environment
  variables such as `PORT` or `HOST` no longer silently change daemon
  settings.
- **Invalid configurations are rejected.** `pyrolab config update` and
  `pyrolab up` refuse a configuration that refers to an undefined nameserver
  or daemon, explaining every problem, and leave the installed configuration
  untouched.
- **A daemon's `port` and `unixsocket` settings now take effect.** They were
  previously ignored, so a daemon with a configured port may now listen
  somewhere new.
- **`pyrolab reload` also starts every `autolaunch` entry,** including any you
  had stopped by hand.
- **`pyrolab stop` needs the name** of what to stop.
- **Instruments are closed when PyroLab is done with them:** when their daemon
  stops, and, for session-mode instruments, when the client disconnects.
  Drivers' `close()` should cope with an instrument that never connected.
- **Some driver errors changed type.** The PPCL55x lasers raise `TimeoutError`
  or `OSError` (a timeout used to return `(0xFF, 0xFF, 0xFF, 0xFF)`), TSL550
  `wavelength_logging` raises `TimeoutError` or `OSError` instead of
  `RuntimeError`, and Arduino `analog_read` raises `TimeoutError` after one
  second instead of waiting forever.
- **The `dev`, `test`, and `docs` extras are gone.** They only held development
  tools, which are now uv dependency groups.

### Added
- `pyrolab status`: whether the daemon is running, and the warnings and errors
  logged since it started (#36).
- `pyrolab logs show`, with `--level`, `--all`, and `--lines`.
- `pyrolab --data` lists where PyroLab keeps its files.
- `pyrolab ps` shows each entity's status (running, restarting, failed) and
  its last error.
- `pyrolab rename --force` replaces an existing entity of the same name.
- `pyrolab up --timeout` and `pyrolab down --timeout`.
- Environment variables `PYROLAB_DATA_DIR` and `PYROLAB_NO_VERSION_CHECK`.
- A `cameras` extra (OpenCV) for the ThorCam and AmScope drivers.
- `analog_read(pin, timeout=1.0)` on the Arduino driver.

### Changed
- `pyrolab up` waits until the daemon responds, reports why it exited if it
  couldn't start, and refuses to start a second daemon. The daemon answers
  requests at once and runs `autolaunch` in the background, so one failing
  entry no longer stops the others (#54).
- Stopping a nameserver or daemon escalates: a stop request, then after 10 s
  `terminate()`, then after 5 s `kill()`. Several are stopped in parallel, and
  a killed daemon's nameserver entries are removed for it (#50).
- A crashed nameserver or daemon is restarted after 5, 15, 60, then 300 s.
  After five crashes in a row it is marked failed until started by hand or
  reloaded. Crashes are noticed within a second (#51).
- Registering with a nameserver no longer takes a daemon down when the
  nameserver is unreachable. It is retried every 30 s, and every nameserver
  call times out after 5 s (#52, #53).
- `pyrolab start` waits for the result and reports it, and no longer starts a
  second copy of something already running. `pyrolab reload` reports failure
  unless everything came back (#59).
- `pyrolab rename` updates every reference to the renamed nameserver or daemon
  (#67).
- Configuration and lockfile writes are atomic, so an interrupted write never
  leaves a half-written file.
- The PyPI update check runs only from the `pyrolab` command, at most once a
  day, with a 2-second timeout, and prints to stderr (#62).
- `pyrolab logs export` writes readable text by default (or `--json`), and
  skips lines it can't read instead of failing (#71).
- `host: public` falls back to a local address instead of crashing on a
  machine with no route to the internet.
- Logs from every process go to one file, written by the daemon alone, so a
  killed process can't block anyone else's logging (#25, #63, #64).
- PyroLab's files live in per-user folders (#66).

### Fixed
- Locks were never released when their client disconnected (#45).
- `start_ns` called itself instead of Pyro's (#44), and `ns_bchost` was typed
  as a bool (#48).
- `from pyrolab import cli` failed (#65).
- Several CLI commands crashed after `pyrolab config reset` (#55, #70), or
  when stopping something not running (#68).
- `ps` crashed while a daemon was starting (#46), and showed wrong uptimes
  such as "Up 60 seconds" (#77).
- A stale or half-written lockfile could block the CLI, and a busy daemon was
  mistaken for a dead one (#56).
- Services with no description registered empty metadata (#76).
- The `multiprocessing` helper process could outlive the daemon (#75).
- PPCL55x lasers hung forever after a single failed read, and their
  communication errors became `NameError`s (#88, #58).
- Bare `except:` clauses hid the original errors (#60).
- The Arduino driver could hang a daemon reading an analog pin (#57), and
  crashed on Python 3.11+ with pyfirmata 1.1.0 from PyPI.
- The RTO driver discarded its VISA resource manager (#79).
- Instruments were only closed by garbage collection, and errors from
  `close()` were lost (#61).
- The motion examples now connect their stages correctly (#41).
- Smaller fixes: #47, #69, #72, #73, #74, #78, #80.

### Removed
- Python 3.9 and 3.10 support.
- The per-process log files (see "One log file" above).
- `requirements.txt`; dependencies are declared only in `pyproject.toml`.

### For contributors
- A test suite that needs no hardware, run by CI on Ubuntu and Windows for
  Python 3.11 to 3.14 (#81).
- uv for environments, locking, and versioning; ruff for formatting (#83).
- Releases publish through PyPI Trusted Publishing, with this changelog as the
  GitHub release notes (#82).
- Read the Docs builds with uv, and builds a preview for every pull request.
